I'll assume you've either watched the video at this point, or are not planning to. Either way, I'll re-state the climax:

Array indexing is:

- a fallible operation
- a partial function

The "oh sh**" moment happens when you realize that both of these bullet points are structurally identical (kinda like an isomorphism) if your language doesn't crash programs on failure, but instead treats it like a side effect that must be handled.

The essence is this:
- there are some inputs which cause failure for fallible operations
- there are some inputs for which the output is undefined for partial functions

To draw the relation between array indexing and functions closer, consider an intermediate object: maps. Actually, with Verse notation, the notation for arrays and maps is very semantically suggestive: maps from `foo` -> `bar` are `[foo]bar`, while arrays are denoted `[]baz`, which implicitly suggests a map like `[int]baz`, from `int` -> `baz`.

Just as a function from `int` -> `baz` can be undefined on some inputs, array indexing can fail for some inputs.

WHICH IS WHY, IN VERSE, WE USE SQUARE BRACKETS FOR FALLIBLE FUNCTIONS!!

---

Failure becomes part of the control flow.

```
Divide[1, 0]   # can fail
Divide[2, 3]   # can fail

Add(1, 0)      # infallible

myArr[0]       # can fail
myMap["bob"]   # can fail
```
